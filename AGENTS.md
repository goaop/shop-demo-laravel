# Agent guidance for goaop/shop-demo-laravel

A Laravel 13 reference application for [Go! AOP](https://github.com/goaop/framework) 4 and
[goaop-laravel-bridge](https://github.com/goaop/goaop-laravel-bridge) 2, and a benchmark of its modes. Read
[README.md](README.md) first.

## Commands

```bash
composer setup              # install, .env, APP_KEY
php artisan test            # feature tests (separate processes, see below)
php bench/smoke.php         # deployment step + two requests in every mode
bash bench/run-all.sh       # every benchmark, writes results/
```

## Constraints of the AOP integration (do not "simplify" these away)

- `GoAopServiceProvider` initializes the aspect kernel at the start of the boot phase. Service providers bind application
  classes **by name** in `register()` (`$this->app->singleton(Foo::class)`); resolving one there loads it unwoven.
- Aspects are listed in `config/go_aop.php` (`aspects`) and resolved through the container on the first advice call.
- `bootstrap/providers.php` registers `GoAopServiceProvider` explicitly (its discovery is off in `composer.json`) only to
  switch it off for the `baseline` benchmark with `GOAOP_ENABLED=false` in the real environment.
- With `PREBUILT_CACHE` (`GOAOP_FEATURES=64`), every artisan command except `aop:warmup` fails while the AOP cache misses
  a class: deployments run `aop:warmup` first, then `php artisan optimize` (the cached configuration keeps the features).
- Woven methods keep their interceptors (and the aspect instances) in static variables for the whole process. Tests that
  create several applications run in separate processes (`#[RunTestsInSeparateProcesses]`).
- `app/Modules/` and `lib/` are generated by `bin/generate.php` (composer `pre-autoload-dump`); never edit or commit them.

## Conventions

- Conventional Commits (`type(scope): summary`).
- No database: sessions, cache and queue use the array/sync drivers (`.env.example`).
